# النسخ الاحتياطي والاستعادة

تُدار المنصة كنسختين متكاملتين. يحتفظ مستودع GitHub بتاريخ ملفات التطبيق والاختبارات ووثائق البنية وملفات Drizzle migrations. لذلك يمكن الرجوع إلى أي التزام سابق إذا حدث خلل في الكود أو الواجهة. تحتفظ قاعدة البيانات بالمحتوى وحسابات المستخدمين واقتراحاتهم، وتُدار بنيتها عبر ملفات migrations الملتزمة في المستودع.

| الأصل | مصدر النسخة | طريقة الاستعادة |
|---|---|---|
| كود المنصة والواجهة والاختبارات | GitHub | استعادة التزام معروف أو إعادة نشر فرع `main` بعد مراجعة التغييرات. |
| بنية قاعدة البيانات | `drizzle/schema.ts` وملفات migrations | إعادة تطبيق migrations بالترتيب على قاعدة بيانات جديدة أو بيئة استعادة. |
| اقتراحات المستخدمين والمحتوى المنشور | قاعدة بيانات المنصة | لا تُحذف في عمليات استعادة الكود؛ يجب نسخ قاعدة البيانات دورياً قبل أي تعديل يدوي كبير. |
| بيانات الجلسة المحلية للعبة | `localStorage` على جهاز اللاعب | تستمر على جهاز المستخدم، ولا تُعامل كنسخة احتياطية خادمية. |

> قبل أي تطوير كبير، احفظ نقطة استعادة للمشروع ثم التزم بالتغييرات إلى GitHub. عند تعديل المخطط، لا تعدّل قاعدة الإنتاج يدوياً؛ أضف migration جديداً أولاً واحتفظ به في المستودع.

## تشغيل نسخة مستعادة

1. اختر التزاماً سليماً من سجل GitHub واستعِد الكود في بيئة التطوير.
2. ثبّت الاعتمادات عبر `pnpm install` ثم شغّل `pnpm test` و`pnpm check`.
3. طبّق migrations المتتابعة على قاعدة بيانات الاستعادة.
4. افحص الحسابات ومسارات الاقتراح والمراجعة قبل إعادة النشر.
